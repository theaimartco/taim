# Wayland and VYOM real-device acceptance

**Status: NOT EXECUTED.** This document describes required evidence. A headless
unit test, a screenshot generated by software, or a green hosted CI job does
not prove real-device functionality. Never mark a test PASS without a named
device, exact commit, reproducible steps, logs and an independent reviewer.

## Hardware inventory

Record the release commit, clean tree status, device serial/asset label
(no private IDs in public artifacts), OS/kernel, CPU, GPU/driver, compositor,
Vulkan renderer, panel resolution/Hz/scale, language and input method, thermal
state, CPU governor, battery/AC power and accessibility bus.

Test both generic winit Wayland and the **native VYOM/Smithay presentation
path** if VYOM is a claimed supported target. A VYOM-shaped UI launched
under another compositor does not test the native backend. If no live
VYOM-native presentation path exists, mark it BLOCKED.

## Build on the physical target

Run from a clean checkout at the candidate commit:

    rustup show
    cargo fmt --all -- --check
    cargo clippy --workspace --all-targets -- -D warnings
    cargo test --workspace
    cargo test --test golden
    TAIM_ATSPI_REQUIRE_BUS=1 dbus-run-session -- cargo test -p taim-accessibility --features atspi --test atspi_bus
    cargo build --release -p taim-showcase
    cargo build --release -p mobile_shell --features taim/measurement

Start the real GUI app while recording exact backend selection, software/GPU
fallback status, compositor logs and presentation feedback. Run separate
software-renderer and accelerated-renderer lanes.

## Mandatory field tests

| Test | Action | Required evidence |
|---|---|---|
| Real presentation | Open, animate, scroll, resize, change fractional scale at supported 60/90/120 Hz | 1000+ actual presentation intervals per run, compositor feedback and image/video evidence |
| Pointer/touch | Hover, capture, multi-touch, cancel, nested scroll, drag across windows | Sanitized event trace, no stuck contacts |
| IME/keyboard | Preedit, commit, delete, select in English, Hindi, Punjabi, Bengali, Tamil, Arabic RTL, emoji | Redacted text roundtrips and event logs, no duplicate commit |
| Screen reader | Real Orca on AT-SPI-enabled desktop, navigate buttons, dialogs, live regions | Accessibility transcript/recording and semantics tree |
| GPU loss | On isolated developer hardware, controlled fault injection; verify recovery or safe software shell | Fault code, renderer recovery trace, no secret surface exposure |
| Lifecycle | Focus change, sleep/resume, monitor hotplug, DPI changes, close/reopen | No stale surface or use-after-free; compositor logs |
| Resource churn | At least 30-minute deterministic navigation, images, 100k rows, animation | RSS and GPU allocation series, leak analysis |
| Idle energy | Screen fixed, 10-minute settle, 60-minute idle session and controlled background workload | Powercap/external-meter trace, CPU wakeups, zero submissions if genuinely idle |

State per test: NOT RUN / BLOCKED / FAIL / PASS. For PASS include evidence
paths, SHA-256 digests, timestamp, exact revision and reviewer. Repeated
crashes or unavailable instrumentation are not passing results.

## Existing process measurement (Linux)

    python3 scripts/perf/measure-app.py \
      --workload 'idle shell on real Wayland target' \
      --warmup 10 --duration 60 \
      --output evidence/idle-process.json \
      -- ./target/release/mobile_shell

The above measurement requires an actual first-present marker. It measures
process-only RSS and observed marker upper bound, and optionally one
powercap energy domain with --energy-counter. It does not measure GPU memory,
actual first visible pixel or input-to-photon latency. Inspect its status,
app exit and warnings; never convert a failure to zero.

Physical input-to-photon requires a calibrated sensor with a synchronized
input actuator and display photodiode/high-speed measurement. Save raw
timestamps, calibration, timebase and uncertainties. Do not substitute
software key-to-raster or input-to-submit time.

## Executable live Wayland preflight

On the actual named Wayland device, from a clean checkout with a working
compositor session, invoke `bash scripts/qa/wayland-smoke.sh /tmp/taim-acceptance-1`.
This script checks the real Wayland socket, captures a hardware inventory,
compiles the probe-enabled shell, launches it, and checks the measured first
successful compositor present marker and process RSS. It records logs and
SHA-256 evidence hashes; it never claims a physical photon or VYOM-native
GPU acceptance without an instrumented device/session and reviewer.
Optional second argument is a readable `energy_uj` counter; 15-second
power measurements are diagnostics only, not a steady-state power verdict.
